# 零明文密钥引用原则

在 Agent 生态中，硬编码密钥（如 OpenAI API Key、GitHub Personal Access Token、AWS AccessKey）是极易发生外泄的高危隐患。

Portico 实行彻底的**零明文密钥（Zero-Plaintext-Secrets）原则**。

---

## 密钥治理铁律

1. **绝对不存明文**：
   - 登记的 Catalog 元数据、自定义页面组件、审计流水中，严禁写入任何明文密码或 API Token。
   - 提交的数据如果包含疑似密钥字段（如检测到以 `sk-` 开头、AWS Access Key ID `AKIA`/`ASIA` 形值、Google API Key `AIza` 形值、PEM 私钥头 `-----BEGIN ... PRIVATE KEY-----`、npm 访问令牌 `npm_` 形值，或带有明文密码属性），写入校验逻辑将直接抛出错误并拒绝落盘。入口 URL 还会扫描查询参数名、查询值与 fragment；文档锚点或路径中的普通词（如 `/auth/token#installation`）不是密钥。区域名 `asia-pacific` 不是 Access Key，散文中提到「private key」但不含真实 PEM 头同样不是密钥。
2. **只引用，不托管**：
   - Agent 与服务若需要认证凭证，应在运行时通过外部专业的密钥管理系统（如 HashiCorp Vault、AWS Secrets Manager 或本地环境变量）自行注入。
   - Portico 只负责登记服务的访问入口，绝不代存、代传任何外部服务的调用密钥。
3. **日志与错误脱敏**：
   - CLI 与 Portal 在报错输出中严禁将可能包含敏感信息的环境变量内容或完整堆栈直接暴露给终端。

---

## 仓库公开面脱敏检查

铁律 1 与 3 由代码在**写入时**执行；本仓库还有一道在**提交时**执行的同向检查，因为这个仓库是开源的：**tracked 文件就是公开面**。

```bash
deno task check:redaction   # 单独运行
deno task test              # CI 里随全量回归一起执行
```

它扫描 `git ls-files` 的每个 tracked 文件（而不是工作树，所以构建产物、本地数据与未跟踪的草稿都不算公开面），拒绝两类值：

- **凭据形值**：与 catalog 校验同一批形状——issuer 前缀族（`sk-`、`ghp_`、`github_pat_`、`glpat-`、`xox[baprs]-` 等）与固定形状族（AWS Access Key ID、Google API Key、PEM 私钥头、npm 访问令牌）。
- **线上内网坐标**：RFC1918、链路本地 `169.254/16`、CGNAT `100.64/10` 的 IPv4 字面量，ULA 与链路本地 IPv6 字面量，以及公网 DNS 不可能解析的单标签主机 URL（如 `http://<intranet-host>:8788/`）。

规则按**形状**而不是按名单：把线上主机名逐个写进检查，等于把它们写进公开仓库——这与 `approve` 处拒绝内网入口坐标是同一条理由。检查抓的是**字面量**：`http://<intranet-host>:8788/` 这类占位符与 `http://$PORTICO_MCP_HOST:8788/mcp` 这类变量引用都不是坐标，因为运行时才解析——这也正是要求写进将提交文件的形态。回环地址是合法占位符，`0.0.0.0` 由部署契约检查负责，二者都不在本检查的拒绝范围内。

失败输出只给 `文件:行:规则:掩码值`，**不回显原值**：公开仓库的 CI 日志本身也是公开面，把泄漏值再抄一遍只会扩大泄漏面。作者按行号在本地即可定位。

### 豁免

豁免只有两种，且都要能被审查：

1. **合成夹具**：凭证检测的测试必须有“长得像密钥”的输入。这类值在**同一行**带合成标记即可——`not-a-real`、`fake`、`dummy`、`synthetic`、`placeholder`、`redacted`（大小写与分隔符不敏感）。标记词刻意收得很窄：`example` / `sample` 在描述真实系统的散文里太常见，用它们会让一行在没人做决定的情况下被放过。
2. **通用示例坐标**：说明规则或验证规则所必需的少数经典地址（例如 RFC1918 区块边界、`192.168/16` 里的通用主机）。它们按**精确值**登记在 `tests/redaction.ts`，每条都写明理由。

测试会断言每条豁免都写了理由、并且**仍然被命中**（某个示例坐标被删掉后豁免条目不删就会失败）。豁免因此不会随时间烂成一片放行。

## 检查的边界（诚实说明）

形状检查抓的是“粘贴进来的线上值”，它不能证明仓库里没有某个长得像普通单词的内网主机名——那样的名字无法在不写下来的前提下枚举。真正的边界仍然是：不要把线上坐标、凭证与环境实值写进将提交的文件，公开面只放变量引用与占位符。
