# 内部工作台 (/internal)

内部笔记台（Internal Workbench）是组织内部工程师与维护 Agent 了解团队资产全貌、跟踪生命周期演进的协作中心。

---

## 访问与鉴权

- **基础路由**：`http://127.0.0.1:8788/internal`
- **鉴权方式**：通过浏览器 Cookie、HTTP Header `Authorization: Bearer <session>` 或 `X-Portico-Session: <session>`。
- **匿名保护**：无会话的浏览器请求得到 `303` 到 `/login?next=<原路径>`，登录后回到原路径；响应里没有记录名、入口或计数。浏览器登录需要 Portal 进程能写会话存储（见 `docs/ops/env-vars.md`），否则 `/login` 会明说这个部署不能在浏览器里登录。

## 页面组成模块

### 1. 计数与待审入口 (Counts)
计数长在导航上，不是一张独立的仪表盘卡片：
- **左侧栏底**：`可见 N 条 · 待审 N 条`，下面写死一句「公开必须经独立审批」——这两个数字是当前身份可见的总数，不随 `q` / `channel` 过滤缩小。
- **顶部 tab 徽标**：`目录 N`、`待审 N`（`待审` 链到 `/internal?state=pending_public`）。
- **`/internal/c` 目录页顶部**：`当前可见 / 待审公开 / 已公开 / 草稿` 四块计数，其中「待审公开」是链到待审队列的只读入口，不是批准按钮。

> 早期文档承诺的「四卡片资产大盘看板（存活服务总数 / 渠道分布数 / 受控版本数）」没有实现，本节改为记录实际渲染的计数。

### 2. 多状态泳道与过滤 (`/internal/c`)
目录页是当前身份可见记录的一张表（名称 / 状态 / 渠道 / 入口 / 版本 / 更新），状态来自这份表：
- **Drafts (草稿)**：处于本地草稿阶段、仅维护者可见的服务。
- **Internal (内部)**：团队日常依赖的生产/测试服务。
- **Pending Public (待审)**：已发起公开申请但尚未签署审批凭证的服务。
- **Rejected (驳回)**：审核不通过、等待维护者修改重新提交的服务。

筛选靠左侧栏的治理状态链接（`/internal?state=…`）以及 `?state=` / `?channel=` 查询参数：`/internal` 与 `/internal/c` 都吃这两个参数，未知值被忽略。**表格本身没有筛选控件**——需要点左侧栏的状态项，或直接带参数访问。

### 3. 详情与治理时间线（`/internal?id=`）
列表和详情在同一页。点一条记录只改 `?id=`，浏览器后退回到上一次选中，不离开工作台。旧的 `/internal/s/:id` 会 303 到这个地址。

详情上按当前身份显示能做的事，不能做的不出现：

- 人类审计者，且不是提交者：待审公开可以 **通过 / 驳回**（可选备注）。
- 人类审计者：已公开可以 **撤回**（可选备注）。
- 维护者或人类审计者：草稿、内部、已拒绝可以 **删除**。待审公开和已公开不能直接删，必须先驳回或撤回，避免绕过公开边界。
- 维护者：草稿、内部、已拒绝可以 **申请公开**（重新提交为公开候选，回到待审）。人类审计者不能提交——提交与审批必须是两个人，所以审计者界面只提示去向，不渲染这个按钮；维护者走 CLI `catalog publish` 也一样。

这些按钮把表单交给 Review 进程（`POST /review/approve|reject|withdraw|remove`，申请公开走 `POST /review/api/submit`，表单只带记录 id，意图恒为公开候选）。Portal 进程仍然不拿目录写权限（它只写 `sessions.json`，见 `docs/roadmap.md`「运行时边界」）。审批记录页只回放已经作出的决定。

表单地址跟着部署声明的审核入口走（`PORTICO_REVIEW_ORIGIN`）：未声明按同源 `/review/*`，声明了绝对 origin 就提交到那个 origin，声明 `off` 时这些按钮**不出现**——这个部署没有 Review 进程，渲染一个必然 404 的按钮等于撒谎。本地 `deno task up` 不代理 `/review`，想在浏览器里点审批就设 `PORTICO_REVIEW_ORIGIN=http://127.0.0.1:8791/review`（表单挂在这个基址下，路径前缀要写进去）。

右侧/底部展开该服务的不可篡改时间线：
- 何时由谁首次登记。
- 何时发起过字段更新（展示具体的增改差分）。
- 何时发起过公开申请，审批人是谁，给出的审计意见为何。

### 4. 待审公开队列 (`/internal/pending`)
已登录身份（只读及以上）看到当前可见的 `pending_public` 候选，与目录过滤 `state=pending_public` 同一批。草稿、内部记录与已公开记录不出现。可按渠道（`cli` / `mcp` / `web`）只读筛选：`/internal/pending?channel=cli` 只保留含该渠道的待审候选；未知 `channel` 静默忽略，仍展示全部。筛选 tab 显示该渠道待审计数（全部 tab 为待审总数）；筛选后其它渠道计数不缩小。内部记录不计入这些数字。入口标明种类（`url` / `package` / `mcp_endpoint`），引用以转义文本展示，不可点击，方便人类审计看公开入口将指向何处。页面无脚本、无表单，不能批准或驳回。匿名访问返回 HTML 404，不泄漏候选名称、入口或渠道计数。已作出的决定在审批记录页。

### 5. 公开边界审批轨迹 (`/internal/approvals`)
已登录身份（只读及以上）看到与 CLI `catalog approvals`、`GET /api/approvals`、MCP `portico_approvals` 同一批通过 / 驳回 / 撤回记录，含可选审计备注。待审公开不会出现在这里。页面无脚本，不能批准或驳回。匿名访问返回 HTML 404，不泄漏记录名或备注。待审候选在待审队列页。

### 6. 专属安全审计台 (`/internal/audit`)
仅向拥有 `auditor` 角色的人类展示：
- 聚合显示全量操作流水（登记、更新、注销、凭证作废、网关放行）。
- 支持按服务 ID 或执行者快速回溯历史安全事件。
- 顶部两块只读面板：**封条校验**（四支柱的 `ok` / 已封条数 / 检查点状态）与**当前判定**（每个主体与作用域的最新审计结论、是否「曾被标记后已清除」、边界契约的 `gate`），分别与 CLI `audit verify` / `audit standings`、`GET /api/audit-verify` / `GET /api/conclusions/standings`、MCP `portico_audit_verify` / `portico_conclusion_standings` 同一载荷。
- 两块面板都无脚本、无表单：门户不能替人类写下或改写任何结论，也不能替审计者下判定。`当前判定` 面板为空表示还没有留下判定，不是「全部通过」。
- 时间切片：筛选表单里的 `asOf` 字段（以及 `?asOf=` 查询参数）把时间线与顶部判定面板一起切到那一刻，面板会标明「当时判定」与读取窗口；「回到当前窗口」链接只丢掉窗口、保留其它筛选。语法是带时区的真实瞬时，裸日期或无时区墙钟得到 `INVALID_INPUT`。时间切片不写任何文件，也不改动结论与目录。
- 谁被切、谁不被切是版面明说的：封条校验面板带 `data-window="current"`，标题旁写着「读取窗口不作用于这一面板：封条校验没有历史模式」，切片时还把截止时刻渲染成 `<time datetime="…">`；判定面板与时间线带 `data-window="as-of"`（切片时时间线另有 `data-asof`）。所以切片页面上「封条 ok」不会被读成「那一刻是好的」——封条问的是此刻的文件，它与窗口无关，不是窗口内的结论。封条同样拒绝被切片：带上 `asOf` 的 `GET /api/audit-verify` 得到 `400 INVALID_INPUT`，而不是悄悄忽略。
