# 发现与推荐 (/public · /public/picks)

公开面只有一个页面层，栏目只有两个：**发现**（`/public`，全部已公开登记，按更新时间）与**推荐**
（`/public/picks`，维护者挑选的公开子集）。两者共用同一报头与同一套设计 token；更细的分类只用标签，没有
第三层导航（`category` 栏目已从记录模型移除）。

---

## 页面版式设计

| 区域 | 内容 |
| --- | --- |
| 报头 | Portico、发现、推荐、搜索公开登记、身份、浅色 / 深色 |
| 提示条 | 本页只呈现已通过独立审批的公开登记。未审批对象不进此页。 |
| 主栏 | 头条：最新一条 `approved_public`。其下是其余公开登记，带标签 chip。 |
| 右栏 | 推荐（前 3 条，链到 `/public/picks`）、标签索引（`?tag=`）、边界提示（不运行 Agent） |

文章页 `/public/s/:id` 以登记记录自身为正文：描述按行分段转义为 `<p>`，标签链接回发现的 `?tag=` 过滤，
已审批的 `mediaUrl` 渲染原生播放器，入口与「为何公开」由治理事实生成。

---

## 搜索与标签（无脚本 GET）

- 报头搜索框是真实表单：`GET /public?q=`，与 CLI `catalog list --q`、`GET /api/catalog?q=`、MCP
  `portico_list` 共用 `parseCatalogQuery`，只在 `publicOnly` 之后过滤。
- 标签索引由公开面所有记录的 `tags` 汇总（按出现次数），每项链到 `/public?tag=`；`?tag=` 与 `?q=` 可
  叠加，筛选页给出结果计数与「清除筛选」。
- 已登录身份的 `?q=`/`?tag=` 同样只命中 `approved_public`：发现页不是内部记录的观察窗。

---

## 推荐是维护者的选择，不是审批

`page set` 挑的 `catalog_card` 按推荐顺序出现在 `/public/picks`，但只渲染跨过审批边界的部分：把内部或
待审记录放进推荐，它也不会出现（放不放是维护者的选择，能不能出现由审批决定）。没有推荐时显示「暂无推荐」，
并指回发现，而不是拿最新记录冒充推荐。

---

## 旧杂志地址

根路径 `/` 与杂志链接不再渲染页面，按路径 302 转发：

| 旧地址 | 转发到 |
| --- | --- |
| `/`、`/?q=`、`/?tag=`、`/?theme=` | `/public`（保留同名参数） |
| `/?id=x`、`/s/x` | `/public/s/x`（另带 `?theme=`） |
| `/?category=…`、`/?channel=…` | 丢弃，只保留 `q`/`tag`/`theme` |

转发只做路径改写、不做目录查找，因此 302 本身不能确认某个 id 是否存在；未审批记录在目的地仍得到不泄漏的
HTML 404。
